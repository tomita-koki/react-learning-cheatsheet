まず、どこを見ればいい？

書き方を忘れた → コード例を見る。意味が分からない → 下の説明を読む。うまく動かない → ファイルの場所・保存・渡すデータを確認しよう。

コード例は用途ごとの抜粋です。ファイル全体を置き換えず、コメントと配置先を確認して使ってください。

React / 01

関数・コンポーネント

コンポーネントは、表示する内容を返す関数。名前は大文字で始めます。

コード例
export default function AboutPage() {
  return (
    <main>
      <h1>自己紹介</h1>
      <p>Reactを学習しています。</p>
    </main>
  );
}
  • function AboutPage()：AboutPageという関数を作る。
  • { ... }：処理を書く場所。return (...)：今回は画面に表示する内容を返す。
  • export default：ファイルの代表として外から使えるようにする。
  • 使うときは <AboutPage />。JSXを書くファイルの拡張子は .tsx。

JavaScript / 02

オブジェクトと配列

オブジェクトは1件の情報。配列は複数件をまとめる入れ物です。

コード例
const work = { id: "school", title: "動画スクールLP" };
work.title; // 作品名を取り出す

const works = [
  { id: "school", title: "動画スクールLP" },
  { id: "sauna", title: "サウナ紹介サイト" },
];
works[0];       // 1件目のオブジェクト
works[0].title; // 1件目の作品名
works.length;   // 2件
  • 配列の番号は0から始まる。
  • worksは「オブジェクトが入った配列」。オブジェクト自体とは区別する。

TypeScript / 03

TypeScriptの型

型は「どんなデータを入れるか」というルール。Workは自分で作った型です。

コード例
export type Work = {
  id: string;
  title: string;
  category: string;
  url: string;
  description: string;
  productionMethod?: string;
  image?: {
    url: string;
    width: number;
    height: number;
  };
};

const works: Work[] = [];
  • string：文字列。number：数値。boolean：trueまたはfalse。
  • Work[]：Work型のオブジェクトが入る配列。
  • productionMethod?：省略してもよい項目。値が存在するか確認して使う。
  • titleがstringなら、title: 123は型エラー。型注釈だけではAPIの実データを自動検証しない。

React / 04

JSXでデータを表示

タグの中でJavaScriptの値を使うときは波括弧 {} です。

コード例
<article className="work-card">
  <h2>{work.title}</h2>
  <p>{work.description}</p>
  <a href={work.url}>作品を見る</a>
</article>
  • 文字を直接書くなら <p>作品一覧</p>。変数なら <p>{work.title}</p>。
  • HTMLのclassは、JSXではclassNameと書く。タグは閉じる。
  • 複数の要素を返すときは、mainやdiv、<>...</>などで囲む。

React / 05

propsでデータを渡す

親がデータを渡し、子が受け取って表示します。関数の引数に似た役割です。

コード例
// 親：作品データを渡す
<WorkCard work={work} />

// 子：受け取ったデータを表示する
import type { Work } from "@/types/work";

export default function WorkCard({ work }: { work: Work }) {
  return <h2>{work.title}</h2>;
}

// 配列を受け取る場合の引数
// { works }: { works: Work[] }
  • work={work} の左側はpropsの名前、右側は渡すデータ。
  • 作品名を変えるときはデータを編集。共通の表示方法を変えるときはWorkCardを編集。
  • このプロジェクトでは @/ は src/ を指す。import typeは型だけの読み込み。

React / 06

stateとクリックイベント

stateは、Reactが覚えておく画面用の値。更新関数を呼ぶと表示も更新されます。

コード例
"use client";
import { useState } from "react";

export default function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(count + 1)}>
      カウント：{count}
    </button>
  );
}
  • count：現在の値。setCount：更新する関数。0：初期値。stateは初期値そのものではない。
  • onClick={addTopic}：クリック時に実行する関数を渡す。
  • onClick={addTopic()}：描画中に関数を実行してしまう。引数を渡すなら () => addTopic(...)。

React / 07

入力欄とリセット

入力欄の文字をstateへ保存し、valueで画面に反映します。

コード例
const [keyword, setKeyword] = useState("");
const [category, setCategory] = useState("すべて");

<label>
  作品名で検索
  <input
    type="search"
    value={keyword}
    onChange={(event) => setKeyword(event.target.value)}
  />
</label>

<button onClick={() => {
  setCategory("すべて");
  setKeyword("");
}}>条件をリセット</button>
  • event.target.value：入力欄に今入っている文字。
  • setKeyword("")がないと、リセットしても検索文字と検索条件が残る。

JavaScript / 08

map・filter・find

filterで作品を絞り、mapでカードへ変換。findでは条件に合う最初の1件を探します。

コード例
const filteredWorks = works.filter(
  (work) =>
    (category === "すべて" || work.category === category) &&
    work.title.includes(keyword)
);

// 絞り込み後の作品をカードに変換
{filteredWorks.map((work) => (
  <WorkCard key={work.id} work={work} />
))}

<p>{filteredWorks.length}件の作品</p>

// URLのidと一致する最初の1件
const work = works.find((work) => work.id === id);
  • ===：同じ値か。||：または。&&：かつ。includes：指定した文字を含むか（大文字・小文字を区別）。
  • filterとmapは新しい配列を作る。findは要素1件を返し、見つからないとundefined。
  • works.lengthは全件数。filteredWorks.lengthは絞り込み後の件数。元のworksは検索しても変わらない。
  • keyはReactが項目を区別する目印。兄弟の間で重複しないIDを使う。

React / 09

条件によって表示する

値があるときだけ表示する、ないときに案内する、2通りを切り替える、の3パターン。

コード例
// 値があるときだけ
{work.productionMethod && (
  <section>
    <h2>制作方法</h2>
    <p>{work.productionMethod}</p>
  </section>
)}

// 画像がないときだけ
{!work.image && <p>画像未登録</p>}

// 0件のときだけ
{filteredWorks.length === 0 && <p>条件に合う作品がありません。</p>}

// 2通りを切り替える
<p>{work ? work.title : "作品が見つかりません"}</p>
  • !は否定。!work.imageは、画像がないときにtrue。
  • 条件 ? 条件を満たす場合 : 満たさない場合。
  • &&の左に数値を直接置くと0が表示される場合がある。件数なら length > 0 などで比較する。

Next.js / 10

Next.jsのページとlayout

フォルダがURLを決め、page.tsxが表示内容を返します。layoutは共通部分です。

コード例
// layout.tsx の構造
<html lang="ja">
  <body>
    <header>共通ヘッダー</header>
    {children}
    <footer>共通フッター</footer>
  </body>
</html>
  • app/page.tsx → /。app/about/page.tsx → /about。
  • app/works/[id]/page.tsx → /works/作品ID。[id]は角括弧を含むフォルダ名。
  • {children}には、現在開いているページの表示内容が入る。
  • ヘッダー・フッターはbodyの中に置く。

Next.js / 11

LinkとURLのID

作品データのIDをリンクに入れ、詳細ページでURLから受け取ります。

コード例
import Link from "next/link";

<Link href="/">実績一覧へ戻る</Link>
<Link href={`/works/${work.id}`}>詳細を見る</Link>
<a href={work.url}>作品を見る</a>

// app/works/[id]/page.tsx
export default async function WorkDetailPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  // /works/school なら id は "school"
}
  • サイト内の移動はLink、公開作品など外部への移動はaを使った。
  • バッククォート内の ${work.id} に値が入る。
  • id：実績サイト内で作品を探す値。url：公開作品サイトの移動先。別の役割。
  • URLの最後の部分と作品データのidを、findで比較する。

Next.js / 12

サーバーとクライアント

サーバーで取得し、ブラウザ側のコンポーネントへ作品データを渡します。

コード例
// app/page.tsx：サーバー側
import { getWorks } from "@/lib/microcms";
import WorkList from "@/components/WorkList";

export default async function Home() {
  const works = await getWorks();
  return <WorkList works={works} />;
}

// WorkList.tsx の先頭：検索などの操作を担当
"use client";
  • 今回のpage.tsxのAPI取得はサーバー側。useEffectは不要。
  • useStateやクリック操作を担当するWorkListに "use client" を付ける。
  • サーバーコンポーネントからクライアントコンポーネントを表示できる。
  • microcms.tsをWorkListから読み込まない。APIキーはpropsにも含めない。

API / 13

async・awaitとmicroCMS

fetchで通信し、JSONのcontentsに入っている作品の配列を返します。

コード例
import type { Work } from "@/types/work";

export async function getWorks() {
  const domain = process.env.MICROCMS_SERVICE_DOMAIN;
  const apiKey = process.env.MICROCMS_API_KEY;
  if (!domain || !apiKey) {
    throw new Error("microCMSの接続設定がありません。");
  }
  const response = await fetch(
    `https://${domain}.microcms.io/api/v1/works`,
    {
      headers: { "X-MICROCMS-API-KEY": apiKey },
      cache: "no-store",
    }
  );
  if (!response.ok) {
    throw new Error("作品データを取得できませんでした。");
  }
  const data: { contents: Work[] } = await response.json();
  return data.contents;
}
  • async：Promiseを返す関数。await：結果を待つ。
  • response.json()：応答のJSONを読み取る。contents：microCMSの一覧配列。
  • fetchは404や500だけでは例外にならないため、response.okも確認する。
  • これは学習用の一覧取得。microCMSの一覧には取得件数の上限・ページ分割がある。作品が増えたら対応が必要。
  • 型注釈は受信データの検証ではない。必須項目はCMS側でも管理する。

Next.js / 14

待機・エラー・404

待っている、処理が失敗した、作品が存在しない、を区別します。

コード例
// loading.tsx
export default function Loading() {
  return <p>作品を読み込み中…</p>;
}

// error.tsx（別ファイル）
"use client";
export default function Error() {
  return <p>作品を取得できませんでした。</p>;
}

// 詳細ページ：作品が見つからないとき
import { notFound } from "next/navigation";
if (!work) {
  notFound();
}
  • loading.tsx：読み込み中。通信が速いと一瞬で終わる。
  • error.tsx：API通信などの処理に失敗。Client Componentが必要。
  • not-found.tsx：notFound()で呼ばれる見つからないページ。
  • 確認用のthrow new Error(...)は関数の中に置き、確認後は削除する。
  • ストリーミング開始後は、404の表示でもHTTPステータスが200になる場合がある。

try / catch / finally の基本

try {
  // 失敗する可能性がある処理
} catch (error) {
  // 失敗したときの処理
} finally {
  // 成功・失敗のどちらでも最後に実行
}

Next.js / 15

ページのタイトル・説明文

generateMetadataで、作品ごとにタブ名やページの説明文を設定します。

コード例
import type { Metadata } from "next";

export async function generateMetadata({
  params,
}: {
  params: Promise<{ id: string }>;
}): Promise<Metadata> {
  const { id } = await params;
  const works = await getWorks();
  const work = works.find((work) => work.id === id);
  return {
    title: work
      ? `${work.title} | 制作実績サイト`
      : "作品が見つかりません | 制作実績サイト",
    description: work
      ? work.description
      : "指定された作品が見つかりません。",
  };
}
  • 本文とメタデータがwork.descriptionを使うので、CMSの変更は両方に反映される。
  • メタデータのdescriptionは画面の本文ではなく、ページ情報。
  • getWorksの読み込みは、この関数を置くファイルにも必要。

表示・CSS / 16

画像とCSSのパターン

画像があるときだけ表示し、CSSで余白と並び方を整えます。

コード例
import Image from "next/image";

{work.image && (
  <Image
    src={work.image.url}
    alt={`${work.title}のスクリーンショット`}
    width={work.image.width}
    height={work.image.height}
    style={{ width: "100%", maxWidth: 400, height: "auto" }}

  • next.config.tsのimages.remotePatternsで、images.microcms-assets.ioの /assets/** を許可した。
  • widthとheightは元画像の寸法。CSSで表示幅を変え、height: autoで比率を保つ。
  • JSXのclassNameとCSSのクラス名をそろえる。
  • aria-pressed={category === "LP"} で選択状態を伝え、CSSでも利用する。

React / 17

useEffectの復習

表示に合わせて、通信やタイマーなど外部の仕組みと連携するときに使います。

コード例
import { useEffect } from "react";

useEffect(() => {
  // 外部の仕組みとの連携

  return () => {
    // 後片付け（cleanup）
  };
}, [nickname]);
  • 依存配列を省略：描画が反映されるたび。[]：マウント時。[nickname]：マウント時とnicknameが変わったとき。
  • cleanupは、依存値が変わって次のEffectを実行する前や、コンポーネントが外れるときに実行される。
  • 開発時のStrict Modeでは、確認のため追加のセットアップ・後片付けが起こる場合がある。
  • 今回のmicroCMS取得はサーバー側なのでuseEffectを使わない。

開発 / 18

起動・チェック・Git保存

week5で起動・チェック。リポジトリのルートでコミット・プッシュします。

コード例
# week5 フォルダで
npm run dev -- --port 3001
npm run lint -- src
npm run build

# リポジトリのルートで
git status
git add week5
git diff --cached
git commit -m "変更内容を書く"
git push origin main
  • localhost:3001はローカル確認用。パソコンで開発サーバーを起動している間だけ使える。
  • add：記録対象を選ぶ。commit：ローカルに記録。push：GitHubへ送る。
  • .env.localのAPIキーはコミットしない。NEXT_PUBLIC_も付けない。
  • GitHubにプッシュすることと、サイトを一般公開することは別。
  • このチートシートはHTML単体でも開ける。作品サイトの起動は不要。

一致する項目がありません。短い単語に変えるか、検索をクリアしてください。
